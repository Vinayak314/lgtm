# LGTM

> *Tinder-like app for group decisions — swipe together, match on the one thing everyone actually wants.*

## Overview
**LGTM** is a mobile app built with Flutter that helps groups of friends, roommates, or family members quickly agree on a shared activity — what movie to watch, or where to eat without the usual back-and-forth of a group chat. 

Users swipe through real options (sourced live from public APIs, not mock data) on their own phones, and the app detects the moment everyone has swiped right on the same thing, revealing it to the whole group instantly.

## Key Features
- **Group Sessions:** Easily invite friends, roommates, or family to a shared decision-making session.
- **Real-time Options:** Swipe through actual, live choices (e.g., movies playing nearby, highly-rated local restaurants) sourced from public APIs.
- **Instant Matching:** The app tracks everyone's swipes and immediately notifies the group the second a unanimous "right swipe" occurs.
- **Cross-Platform:** Built with Flutter for a smooth experience on both iOS and Android.

## Tech Stack
- **Frontend Framework:** Flutter
- **Backend:** Firebase Auth + Realtime Database (project `lgtm-app`)
- **State:** Provider
- **Data Integration:** Various Public APIs (Movies, Places/Restaurants, etc.)

## Setup

The Firebase config files are **not** in the repo, so an Android build needs one download before it will run:

1. Open the [Firebase console](https://console.firebase.google.com/project/lgtm-app) and sign in.
2. **Project settings → Your apps → the Android app → Add Firebase to your Android app**, or open the app you already added and download `google-services.json`.
3. Put that file at `android/app/google-services.json`. The Gradle plugin reads it from there, so a fresh clone plus that one file is a working Android build.

For iOS, download `GoogleService-Info.plist` from the same page and add it to the `Runner` target in Xcode. The app runs on Android only for now: `lib/firebase_options.dart` returns options for Android and throws for every other platform, so iOS needs `flutterfire configure` re-run on a Mac (and `pod install`) before it will start.

Both files are git-ignored on purpose: they are per machine, and `google-services.json` is the same API key that `lib/firebase_options.dart` already carries (that file is committed, because Flutter needs it on every platform). The key only identifies the project — every read and write is still decided by `database.rules.json`.

```bash
flutter pub get
flutter run
```

## Firebase

`lib/firebase_options.dart` is generated by `flutterfire configure` and is committed; `android/app/google-services.json` is generated by the Firebase console and is not — see [Setup](#setup) above.

```bash
# Sign in once per machine
firebase login

# Realtime Database rules, before they reach production
firebase emulators:start --only database --project lgtm-app

# What the rules allow and deny, against that emulator
cd tool/rules && npm install && cd ../..
node tool/rules/rules_test.mjs

# Ship the rules
firebase deploy --only database --project lgtm-app
```

The rules suite writes profiles, groups, invite codes, sessions and votes as different accounts and asserts both what is allowed and what is refused. `tool/rules/node_modules` and `tool/rules/package-lock.json` are ignored by git.

Data layout:

```text
users/{uid}         { name, email, fcmToken }
userGroups/{uid}    { gid: true }        // the groups this member is in
groups/{gid}        { name, code, ownerId, kind, createdAt, activeSession,
                      members: { uid: true } }
inviteCodes/{CODE}  gid
sessions/{sid}      { groupId, hostId, status, category, radius, cards,
                      participants: { uid: true }, votes, winner }
```

`userGroups` exists because the database grants a query only when the whole queried path is readable. Querying `groups` would mean reading every group in the app.

## Demo mode

A build can run on the in-memory mocks instead of Firebase: no project, no rules, no network, and the groups it starts with are the seeded ones.

```bash
# On a device or emulator
flutter run --dart-define=LGTM_DEMO=true

# An installable demo APK
flutter build apk --debug --dart-define=LGTM_DEMO=true
```

| | |
|---|---|
| Email | `demo@lgtm.app` |
| Password | `lgtm-demo` |
| Groups | Roommates (`vYzA1`, three finished sessions), Hackathon Squad (`x7ZA1`) |
| Signed in as | Purva, the mock member every screen marks as you |

Any filled in pair signs in, because the mock is what the demo runs on. The login screen shows this card, and tapping it fills the form, so nothing has to be guessed or typed by hand.

The flag lives in `lib/app/demo_mode.dart`. `main.dart` skips initialising Firebase when it is on and hands `LgtmApp` no repositories, which is what every screen already falls back to when it has none. Without the flag the app talks to `lgtm-app` exactly as before.
